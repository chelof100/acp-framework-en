1. System Model

We define the ACP system as a set:

S = (A, K, T, R, V)

Where:

A = set of agents

K = set of cryptographic key pairs

T = set of issued tokens

R = set of resources

V = verification function

2. Formal Definitions
2.1 Agent

An agent a ∈ A is defined as:

a = (pk_a, sk_a)

Where:

pk_a is the public key

sk_a is the private key

The agent's identity is:

AgentID_a = H(pk_a)

Where H is SHA-256.

2.2 Capability Token

A token t ∈ T is a tuple:

t = (ver, iss, sub, cap, res, iat, exp, nonce, deleg, parent, rev, sig)

The signature is defined as:

sig = Sign_sk_iss ( H( payload ) )

Where payload includes all fields except sig.

3. Verification Function

We define:

V(t, op, r, time) → {0,1}

Where:

t is token

op is requested operation

r is resource

time is current time

The function returns:

1 if authorized

0 if rejected

4. Validity Conditions

A token t is valid if and only if:

4.1 Valid signature
Verify_pk_iss ( sig , H(payload) ) = 1

4.2 Not expired
iat ≤ time ≤ exp

4.3 Resource match
r ∈ scope(res)

4.4 Capability match
op ∈ cap

4.5 Valid delegation

If parent exists:

t_parent exists

depth ≤ max_depth

cap_child ⊆ cap_parent

res_child ⊆ res_parent

Formally:

∀c ∈ cap_child → c ∈ cap_parent

5. Threat Model

We assume adversary D with capabilities:

Intercept traffic

Replay messages

Attempt to forge tokens

Attempt to modify tokens

Attempt to expand delegations

Compromise individual agent

We do not assume breaking of cryptographic primitives.

6. Security Properties

ACP MUST satisfy:

6.1 Integrity

Computational impossibility of modifying a token without invalidating the signature.

Reducible to:

EUF-CMA security of Ed25519

If Ed25519 is secure → integrity guaranteed.

6.2 Authenticity

Only the holder of sk_iss can generate sig.

Formally:

Forgery probability:

Pr[ Forge(sig) ] ≤ ε

Where ε is negligible under EUF-CMA security.

6.3 No Privilege Escalation

Delegation satisfies:

cap_child ⊆ cap_parent
res_child ⊆ res_parent

By induction over the chain:

If satisfied at each level, then:

cap_final ⊆ cap_original

No expansion is possible without breaking the signature.

6.4 Replay Resistance

Let challenge be generated by R.

I responds with:

Sign_sk_sub ( challenge )

If challenge is unique and non-reusable:

Replay without private key is impossible.

Replay with token but without private key fails proof of possession.

6.5 Revocation

Abstract model:

We define function:

Revoked(t) ∈ {0,1}

The total validity is:

Valid(t) = Signature ∧ Time ∧ Delegation ∧ ¬Revoked(t)

7. Confinement Property

If an initial token t0 defines:

cap0, res0

And a chain exists:

t0 → t1 → t2 → ... → tn

Then:

capn ⊆ cap0
resn ⊆ res0

Proof by induction:

Base:
t1 ⊆ t0

Inductive step:
if ti ⊆ ti-1 and ti-1 ⊆ t0 → ti ⊆ t0

By transitivity:

No valid escalation exists within the system without a cryptographic break.

8. Trust Model

ACP is:

Trust-minimized

Does not depend on constant online authority

Based on cryptographic verifiability

Required trust:

Security of Ed25519

Security of SHA-256

Correct management of private keys

9. Critical Assumptions

The model assumes:

Secure CSPRNG

Private keys not compromised

Correct implementations

No breaking of cryptographic primitives
